# 05 · 排错手册

出问题先**看日志**，不要猜。两个平台的日志位置：

| 路线 | 日志 |
|---|---|
| 1.16.1 | `<游戏目录>\ipxwrapper.log`、`pluto.log`、`bwapi-data\write\` |
| 重制版 | `<桥接目录>\runtime-multiplayer\bridge.log`、`pluto.log` |

---

## 一、重制版

### 日志里的三个关键判据

只找这几行：

```
{"stage":"session_accepted", ...}                                  ✅ 对局被接受，AI 已接管
{"stage":"session_skipped","reason":"...","game_type_name":"..."}  ❌ 被拒，看 reason
{"failure":"bridge_exception","code":3221225477, ...}              💥 崩溃（访问违例）
```

### 症状对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| 注入脚本报"没有找到正在运行的星际" | KK 还没把游戏拉起来 | 先在 KK 里进房间 |
| `Unsupported or damaged file` | 游戏或 Pluto 版本不对 | 核对 [THIRD-PARTY.md](../THIRD-PARTY.md) 的哈希表；重制版必须是 `13515` **x86** |
| `Missing bin/pluto-scr.dll` | 桥接文件不全 | 重新获取桥接 |
| 桥接就绪，但 AI 完全不动 | **游戏方式不是 Melee** | 建房时改成 `Melee`，2 名真人。看日志 `reason` |
| `reason: unsupported_game_type` | 同上（多半用了「上方vs下方」） | 改用 Melee；想打 1vN 用 `-Challenge` |
| `reason: requires_two_players` | 参与者不是 2 人 | 普通模式必须正好 2 人 |
| `reason: local_allies_not_supported` | Pluto 那队有盟友 | Pluto 必须单独一队 |
| **第一局正常，第二局没 AI** | 桥接在对局末期崩溃了 | 用 `-Watch` 自动重注入；崩在同一进程内要重启游戏 |
| 游戏内出现 `this machine can't keep up (… stalling the game …)` | **联机环境变量没生效** | 用带环境变量的方式启动 KK，**并重启平台**，见 [04](04-性能调优.md) |
| AI 决策很慢、游戏被拖慢 | CPU 没有 AVX-VNNI | 见 [04 · 性能调优](04-性能调优.md) |
| 注入时报 Bridge loading failed | 权限或杀软拦截 | 用管理员运行；把桥接目录加入杀软白名单 |

### 崩溃怎么判断

`code: 3221225477` = `0xC0000005` 访问违例。看 `address` 字段：

- 不同机器上崩溃地址的**低位偏移相同**（例如都以 `57C3` 结尾）→ 是同一个可复现的上游 bug
- 崩溃后桥接彻底失效，**必须重启游戏重新注入**

这是实验性项目的固有代价，上游仓库已下架，暂时无人修复。

## 二、1.16.1

| 现象 | 原因 | 处理 |
|---|---|---|
| **`无法初始化网络提供商`** | 同机用了「本地局域网(UDP)」 | UDP 6112 被独占。改走 **IPX**，见 [02](02-1.16.1-安装与同机联机.md) |
| 两个实例互相看不见对局 | **IPX 节点号重复** | 第二个实例必须用独立 Windows 账号 |
| 日志有 `bind(.../6112)` 但**没有** `bind address:` 行 | **IPXWrapper 互斥体冲突** | 第二个实例必须从**影子目录**启动（改过名的 DLL） |
| 日志里出现 `implicit bind` 回退到 1024/1025 | 同上 | 同上 |
| AI 不接管 | BWAPI 没注入成功 | 检查 `bwapi.ini` 的 `ai=` 路径、`bwapi-data\BWAPI.dll` 是否存在 |
| Chaoslauncher 报 `Could not obtain SeDebugPrivilege` | 没用管理员运行 | 右键 → 以管理员身份运行 |

### 验证同机联机成功的标准

`ipxwrapper.log` 里**同时出现两个不同节点号**，且两边都有 `bind address: .../6112`：

```
Node: B0:A4:60:DA:7F:23      ← AI 实例
Node: 02:00:00:00:00:01      ← 人类实例
bind address: 00:00:00:01/B0:A4:60:DA:7F:23/6112
```

## 三、通用排查思路

这一路排查下来，最有用的方法其实是固定的：

1. **先看日志，不要看现象。** 现象会骗人（"连不上"可能是端口、可能是节点、可能是互斥体）。
2. **对比成功和失败两次的记录。** 比如同一个 `bind(.../6112)`，成功时后面跟一行 `bind address:`，失败时没有 —— 这一处差异直接指向根因。
3. **现象描述要具体到"哪一步、什么提示"。** "连不上"没法定位，"进选连接界面弹无法初始化网络提供商"能立刻定位。
4. **搞清楚软件在做什么，而不是猜。** 上游是开源的就去读源码（本项目所有根因都是读源码找到的）。

完整的排查实录见 [06 · 探索过程记录](06-探索过程记录.md)。

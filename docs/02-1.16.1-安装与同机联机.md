# 02 · 1.16.1 安装与同机联机

经典版是 Pluto 官方支持的环境，**成熟、稳定、不锁版本**。想长期用、做系列内容，走这条线。

---

## 一、需要什么

| 组件 | 说明 |
|---|---|
| 星际争霸：母巢之战 **1.16.1** | 自备 |
| **BWAPI 4.4.0** | AI 接口，LGPL-3.0，GitHub Releases 获取 |
| **Chaoslauncher** | 注入器（要用 **MultiInstance** 那个变体），社区获取 |
| **Pluto** 发布版 | 见 [THIRD-PARTY.md](../THIRD-PARTY.md) |
| **IPXWrapper** | **只在同机双开时才需要**，GPL-2.0 |

## 二、装 Pluto

Pluto 的文件按它原本的目录结构放，**不要改**：

```
<游戏目录>\bwapi-data\AI\pluto.dll              ← 32 位 BWAPI 模块
<游戏目录>\bwapi-data\AI\pluto\pluto_infer.exe  ← 64 位推理引擎
<游戏目录>\bwapi-data\AI\pluto\pluto_weights.bin
```

然后在 `<游戏目录>\bwapi-data\bwapi.ini` 里指向它：

```ini
[ai]
ai = bwapi-data/AI/pluto.dll
```

装好之后在 Chaoslauncher 里勾上 BWAPI Injector：

![Chaoslauncher 挂载 BWAPI](../assets/01-classic-chaoslauncher.png)

![指定 Pluto 路径](../assets/03-classic-pluto-path.png)


**单机跑**：

1. Chaoslauncher - MultiInstance → 勾上 `BWAPI 4.4.0 Injector [RELEASE]` → Start
2. 游戏里：Single Player → Expansion → 选角色 → Play Custom
3. 设置选 **Melee / 1 个 Computer**
4. 开局后聊天框会出现 `Pluto online (md07x02_cog2026_2578600_int8mv). gl hf!`

> 注意：单机模式下 Pluto 接管**你那一方**，你自己动手会和 AI 的指令混在一起 —— 所以只移动画面看。

![一键启动脚本](../assets/04-classic-launcher.png)

## 三、同机联机（你和 AI 在一个 PC 上打）

这才是重点。**Pluto 是 BWAPI 模块，必须作为独立玩家参战，所以需要两个星际实例**。而在同一台机器上让两个星际联机，有两个坑。

### 为什么不能用「本地局域网(UDP)」

星际 1.16.1 的 LAN UDP 会**独占绑定 UDP 6112（和 6111）**，且不带 `SO_REUSEADDR`。同机第二个实例抢不到端口，会报：

> **无法初始化网络提供商。**

注册表里那个 `Game Data Port` 键对 LAN **无效**（实测：无论设成什么，会话绑定的始终是 6112/6111）。

**所以同机联机必须走「本地局域网(IPX)」。**

### 坑 1：IPX 节点号重复

IPXWrapper 的配置存在 `HKCU\Software\IPXWrapper\<网卡MAC>`，**同一个 Windows 用户下两个实例读到的是同一份**，于是两个实例的 IPX 节点号一模一样。星际会把对方发来的包当成自己发的丢掉。

**解法**：让第二个实例用**独立的 Windows 账号**（HKCU 独立 → 节点号独立）。

用本仓库脚本一键完成：

```powershell
.\scripts\1161\03-setup-same-pc.ps1
```

它会：创建账号 → 写入该账号的 IPXWrapper 配置（指定一个独立节点）→ 建好启动器。

### 坑 2：IPXWrapper 的具名互斥体（这个是最后卡住的）

即使节点号不同了，还是连不上。因为 IPXWrapper 源码里有这么一段：

```c
snprintf(mutex_name, ..., "ipxwrapper_socket_%hu", socket);
HANDLE mutex = CreateMutex(NULL, FALSE, mutex_name);
if(GetLastError() == ERROR_ALREADY_EXISTS && exclusive) return NULL;  // ← 绑定失败
```

**互斥体名字是纯字符串、不含用户或进程信息**，所以同一个登录会话里**跨用户也照样互撞**。星际固定绑 IPX socket 6112，第二个实例拿不到互斥体就绑不上。

**而且这条失败分支一行日志都不打** —— 日志里只会看到 `bind(.../6112)` 后面没有 `bind address:` 行，然后回退到 socket 1024/1025（收不到对局查询）。

**解法**：让第二个实例从一个**影子目录**启动，里面放一份**只改了 1 个字节**的 `ipxwrapper.dll`：

```
"ipxwrapper_socket_%hu"  →  "jpxwrapper_socket_%hu"
```

两边互斥体命名空间互不干扰，各自进程内的语义完全不变。**原 DLL 一个字节不动。**

脚本已包含这一步。影子目录用「目录联接 + 硬链接」建成，**不占额外磁盘空间**。

### 完整流程

```powershell
# 一次性部署
.\scripts\1161\03-setup-same-pc.ps1

# 以后每次对战：
# ① AI 实例：Choolauncher - MultiInstance → 勾 BWAPI Injector → Start
# ② 人类实例：双击脚本生成的「启动人类实例.cmd」
# ③ 两边都进：多人游戏 → 本地局域网(IPX)
# ④ 一边创建、一边加入，用不同角色名
```

### 怎么确认成功

看游戏目录下的 `ipxwrapper.log`，应该**同时出现两个不同的节点号**：

```
Node: B0:A4:60:DA:7F:23      ← AI 实例
Node: 02:00:00:00:00:01      ← 人类实例
```

并且两边都有 `bind address: .../6112`（**不再出现** `implicit bind` 回退到 1024/1025）。

![本机 IPX 联机成功](../assets/05-classic-ipx-lan.png)

## 四、两台机器联机（比同机简单得多）

如果你有两台电脑，**完全不用上面的东西**：

1. 两台都装好星际 1.16.1
2. AI 那台：Chaoslauncher + BWAPI 注入 + Pluto
3. 人类那台：什么都不用装，正常进游戏
4. 两边都进：多人游戏 → 本地局域网(IPX)（或 UDP，两台机器没有端口冲突）
5. 一边创建、一边加入

**注意**：AI 那台必须装 IPXWrapper（因为 1.16.1 在现代 Windows 上没有 IPX 支持），另一台也要装。

## 五、常见问题

| 现象 | 原因 |
|---|---|
| `无法初始化网络提供商` | 走了 UDP 且同机第二个实例；改用 IPX |
| 两个实例互相看不见 | IPX 节点号重复 → 检查是否用了独立账号 |
| 日志有 `bind(.../6112)` 但没有 `bind address:` | IPXWrapper 互斥体冲突 → 检查是否从影子目录启动 |
| AI 不接管 | 检查 `bwapi.ini` 的 `ai=` 路径、`bwapi-data\BWAPI.dll` 是否存在 |
| 提示 `this machine can't keep up` | CPU 偏慢，见 [04 · 性能调优](04-性能调优.md) |

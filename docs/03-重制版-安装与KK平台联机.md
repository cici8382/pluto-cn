# 03 · 重制版安装与 KK 平台联机（国内整合流程）

本篇是**国内环境**下的完整整合过程 —— 也就是本仓库最核心的内容。

> ⚠️ **实验性**：上游桥接作者自己标注"联机双端同步尚未验证完"，且原仓库已下架。请先读 [01 · 原理](01-原理与版本选择.md) 了解风险，再决定是否投入。

---

## 一、适用条件（缺一不可）

| 条件 | 要求 | 为什么 |
|---|---|---|
| 客户端版本 | **`1.23.10.13515`** | 桥接锁死了这一个构建的内存偏移 |
| 客户端架构 | **必须 x86**（`\x86\StarCraft.exe`） | x64 的 `\x86_64\starcraft.exe` 不是桥接目标 |
| Pluto 版本 | `md07x02_cog2026_2578600_int8mv` | 桥接会校验 SHA256，版本不对拒绝运行 |
| 系统 | Windows 10/11 64 位 | 推理引擎是 64 位独立进程 |
| CPU | 支持 AVX2 | 见 [04 · 性能调优](04-性能调优.md) |

**先做这一步**：确认你的客户端版本和架构。跑 `scripts\scr\01-check-env.ps1`，它会同时告诉你 CPU 指令集情况（影响速度，见第 04 篇）。

---

## 二、原理（一句话）

桥接**不启动游戏**，它是**按 PID 注入**到已经运行的游戏进程里的：

```
scr-loader.exe <游戏进程PID> <pluto-scr.dll 路径>
```

这一点决定了整个流程：**让 KK 平台去启动游戏**（它负责房间和联网），**我们只负责把 AI 挂上去**。

---

## 三、步骤

### 步骤 1：确认 KK 平台用 x86 客户端启动

这是国内环境最容易卡住的一步。KK 平台的配置文件：

```
<KK安装目录>\config\custom\platform.ini
```

里面这一段决定了它启动哪个客户端：

```ini
[SCGame]
SCRRootDir=G:\StarCraft\x86
```

**必须是 `\x86`，不能是 `\x86_64`。** 如果写的是 x64，改成 x86 后再继续（改之前先完全退出 KK 平台）。

> ⚠️ **这个设置会被 KK 改回去 —— 每次开 AI 前都确认一遍。**
>
> 实测遇到过：改成 `\x86` 之后，正常玩几局（或平台更新、切换游戏）再回来，它自己又变回 `\x86_64` 了。一旦变回去，桥接就找不到注入目标，表现是"脚本报没有找到运行中的星际"或者注入了但 AI 不动。
>
> **所以养成习惯：每次开 AI 前先跑一次检测脚本。**

```powershell
.\scripts\scr\01-check-env.ps1
```

它会直接告出 `[OK] KK is set to launch the 32-bit client` 还是 `[FAIL] KK is configured to launch the 64-BIT client`。看到 FAIL 就回去改 `platform.ini`。

### 步骤 2：获取组件并校验

需要两样东西：

1. **Pluto 发布版**（含 `pluto.dll` + `pluto\pluto_infer.exe` + `pluto\pluto_weights.bin`）
2. **重制版桥接**（含 `bin\pluto-scr.dll` + `bin\scr-loader.exe` + `scripts\start-pluto.ps1`）

获取途径和镜像见 [THIRD-PARTY.md](../THIRD-PARTY.md)。**拿到后务必校验**：

```powershell
.\scripts\scr\02-verify.ps1 -Pluto <pluto.dll 路径> -Bridge <桥接目录>
```

看到 `校验通过` 才继续。哈希表在 [THIRD-PARTY.md](../THIRD-PARTY.md)。

### 步骤 3：配置联机环境变量

联机模式需要让推理节奏和游戏的**网络锁步时钟**对齐，否则会卡顿。这两个变量必须传给**游戏进程**：

```
BWRL_STRADDLE=1
BWRL_FRAME_BUDGET_MS=10
```

**关键点**：游戏是 KK 平台拉起来的，所以游戏继承的是 **KK 平台的环境变量**。

最可靠的做法是**启动 KK 时就带上这两个变量**（本仓库提供一个启动器，见 `scripts\scr\launch-kk.cmd`）。

> 常见错误：用 `setx` 设了变量但**没重启 KK 平台** —— 那游戏进程照样拿不到。日记里会出现
> `Pluto: this machine can't keep up (… stalling the game ~42 ms per decision)`，
> 这就是没生效的证据。

### 步骤 4：开 KK，进房间，让平台把游戏拉起来

先完全退出 KK 平台，再用带环境变量的方式启动它，然后照常进房间。

### 步骤 5：注入 AI

```powershell
.\scripts\scr\03-inject-kk.ps1
```

脚本会：校验哈希 → 找到 KK 启动的 x86 星际进程 → 写好 `bridge.ini` → 注入 → 等 `MH_OK`。

看到 `桥接已就绪` 就是成功了。

**连续直播建议挂监视模式**（KK 每局会重新拉起游戏，桥接也会随上一局一起结束）：

```powershell
.\scripts\scr\03-inject-kk.ps1 -Watch
```

开着不用管，每出现一个新的游戏进程就自动注入一次。

### 步骤 6：建房

进游戏后：**Multiplayer → Expansion → 自定义房间**

**游戏方式必须选 `Melee`（近战/混战），2 名真人玩家。**

房间名建议写成 `Pluto AI 1v1` 之类，让对面知道在和一个 AI 打。

## 四、关键限制（必读）

桥接内部有个对局准入检查，不通过会在**屏幕上打韩语提示**并记进日志。规则如下：

| 规则 | 说明 |
|---|---|
| **只认 Melee** | 游戏方式必须是 `Melee`。**`上方vs下方`(Top vs Bottom)、`FFA` 一律拒绝** —— 除非用挑战模式 |
| **必须 2 名真人** | 普通模式要求参与者正好 2 人 |
| **不能有盟友** | Pluto 有盟友的团战不支持（模型会把其他玩家一律当敌人） |
| **不支持** | 录像、战役、RPG/自定义地图（Use Map Settings）、Team Melee 共享单位 |

**想打 1vN 或 上方vs下方**：用挑战模式

```powershell
.\scripts\scr\03-inject-kk.ps1 -Challenge
```

挑战模式下 Top vs Bottom / FFA 才会被允许，且 **Pluto 必须单独在一队**，人类全放对面（支持 2–8 人）。

> ⚠️ 挑战模式作者只验证了 1v1 模型能读多个敌人，**多线战斗力和胜率预测未经验证**，先用 1v2 试。

## 五、验证与排错

### 日志位置

```
<桥接目录>\runtime-multiplayer\bridge.log     主日志
<桥接目录>\runtime-multiplayer\pluto.log      AI 自己的日志
```

### 三个关键判据

出问题先看 `bridge.log`，只找这几行：

| 日志内容 | 含义 |
|---|---|
| `{"stage":"session_accepted",...}` | ✅ 对局被接受，AI 已接管 |
| `{"stage":"session_skipped","reason":"...","game_type_name":"..."}` | ❌ 被拒，看 `reason` 和游戏方式 |
| `{"failure":"bridge_exception","code":3221225477,...}` | 💥 桥接崩溃了（`3221225477` = 访问违例） |

**常见 `reason`：**

- `unsupported_game_type` → 游戏方式不是 Melee（最常见，多半是用了「上方vs下方」）
- `requires_two_players` → 参与者不是 2 人
- `local_allies_not_supported` → Pluto 那队有盟友
- `multiplayer_not_enabled` → 没加 `-Multiplayer`（本仓库脚本默认已加）

### 已知问题：对局末期崩溃

**现象**：第一局正常，第二局 AI 完全不动。

**原因**：桥接在对局末期/退回大厅的路径上会崩溃（访问违例），崩溃地址偏移在不同机器上一致（如 `…57C3`），是可复现的上游 bug。桥接一旦崩溃就死了，**第二局自然没有 AI**（日志里连 `session_skipped` 都不会有）。

**处理**：

- 用 `-Watch` 监视模式，让它每局自动重新注入
- 如果崩溃发生在**同一个进程内**（不是新进程），需要退出游戏让 KK 重新拉起来
- 把这个当成实验性项目的固有代价 —— 上游已下架，暂时无人修复

## 六、把 AI 的速度调好

联机时**游戏速度由游戏控制**，AI 跟不上会拖慢对局。你的机器能跑多快，取决于 CPU 是否支持 AVX-VNNI —— 详细判断和调优见 [04 · 性能调优](04-性能调优.md)。
